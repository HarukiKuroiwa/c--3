# set3 座席の同時販売

## このプログラムがやりたいこと
10万席を4つの窓口（スレッド）が同時に販売する。売れた合計がちょうど10万枚、残り座席が0になるのが正しい。

## 期待される出力
```
sold  = 100000 (expected 100000)
seats = 0 (expected 0)
```

## 症状
`make run` を実行すると、10万枚より多く売れてしまう（売りすぎ）。残り座席がマイナスになることもある。

## 課題
1. `make run` を何回か実行して症状を確認する
2. このプログラムは **mutex を使っている** のに、なぜ排他制御になっていないのかを説明する
3. `problem.c` を修正し、`make check` が **PASS** になれば完了
   （5回実行して5回とも一致し、さらにスレッド用サニタイザで競合が検出されないことが条件）

## ヒント
- mutex は「何を」守るためのものか。`lock` を何個作っているか数えてみよう
- **1か所直しただけでは、まだ足りない**。売りすぎが1〜2枚に減って、たまに正しい結果も出る状態になったら、
  まだバグが残っている。「残り1席のときに、2つの窓口が同時に `sell` を呼んだら」を考えよう
- `make check` の `-fsanitize=thread` は、mutex で守られていない読み書きを報告する。どの行が報告されるかを見よう
- この問題の Makefile は最適化を切っている（`-O0`）。最適化するとバグの出方が変わるため
