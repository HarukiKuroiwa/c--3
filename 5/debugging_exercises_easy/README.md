# デバッグ演習 (easy)

C言語でよくある5種類のバグを、**症状を見る → 原因を突き止める → 直す → 判定する** の順で体験する演習です。

| 問題 | テーマ | 症状 |
|---|---|---|
| `01_array_bounds` | 配列の範囲・初期化 | 最大値がおかしい |
| `02_string_manipulation` | 文字列バッファ | 異常終了する |
| `03_null_pointer` | NULLポインタ | Segmentation fault |
| `04_integer_overflow` | 整数オーバーフロー | 13! 以降の値がおかしい |
| `05_race_condition` | 競合状態 | 実行ごとに合計値が変わる |

## 進め方（各問題のフォルダで）

```bash
cd 01_array_bounds
cat README.md     # 期待される出力と症状を読む
make run          # 症状を自分の目で確認する
                  # → problem.c を調べて修正する
make check        # 判定。PASS なら完了
```

## make check が見ていること

1. **コンパイル**：警告が出ていれば表示します（バグの手がかりになることが多い）
2. **出力の比較**：実行結果が `expected.txt` と一致するか
3. **サニタイザ**：出力が正しく見えても、配列の範囲外アクセスや未定義動作が残っていないか

3つすべてが OK になると **PASS** です。全問まとめて判定するにはこのフォルダで `make check` を実行します。

## 注意

- 修正するのは `problem.c` だけです。`expected.txt` や `Makefile` は変更しないでください
- 「出力が期待値と同じになった」だけでは完了ではありません。**なぜそのバグで、なぜその修正で直るのか** を説明できるようにしてください
- Mac では `gdb` の代わりに `lldb` を使います

## 提出のしかた

1. `REPORT.md` に学籍番号・氏名と、各問題の 1〜5 を書く（見出しは変えない）
2. このフォルダで次を実行する
   ```bash
   make submit ID=学籍番号
   ```
3. できた `submit_…_学籍番号.zip` を提出する

PASS していない問題があっても提出できます。その場合も、分かったところまでをレポートに書いてください。

## AIの使い方と作業記録

- AI に質問しながら進めてもかまいません。ただし、AI の答えを **自分で実行して確かめる** こと。
  使った場合は `REPORT.md` の「AIの利用」に、何を聞き、どこを自分で確かめたかを書いてください
- レポートの「5. 観察と調べ方」には、**自分の環境で実際に見た出力や値** を貼ってください。
  これが書けていない問題は満点になりません
- `make run` と `make check` を実行するたびに、時刻・結果・`problem.c` の変更点が `.worklog/` に自動で記録され、
  提出ファイルに含まれます。消したり書き換えたりしないでください
